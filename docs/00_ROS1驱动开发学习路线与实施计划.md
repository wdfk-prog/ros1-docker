## 阶段 C：AGV 数据链路与 Navigation（13～19）

目标不是转型成导航算法工程师，而是能够理解驱动数据怎样进入坐标变换、状态估计、建图、定位、代价地图和规划，并能沿这条链路定位接口问题。

第 12 章已经完成 `Twist`、`JointState`、`Imu`、`Odometry`、covariance、坐标系约定和差速底盘正/逆运动学，因此阶段 C 不再单独重复“Odometry、Encoder、IMU 与运动数据”。后续章节直接消费第 12 章已经建立的数据契约。

### 13：TF / tf2 与移动机器人坐标系

深入理解：

```text
map
 -> odom
 -> base_link
 -> sensor frames
```

重点：先区分 `/odom` Topic、`odom` 里程计坐标系和 `odom -> base_link` 变换，再理解刚体变换的平移/旋转、求逆和链式组合；继续深入 `TransformListener -> BufferCore -> TimeCache/StaticCache`、`lookupTransform()` 查链算法、时间插值、TF authority、extrapolation，以及“消息有 `frame_id` 不等于 TF 已经存在”。

### 14：URDF / robot_state_publisher / joint_state

理解整机几何关系、link/joint、fixed joint 与运动关节如何建立机器人自身的 TF tree；重点区分 URDF 中的几何关系、`joint_states` 中的关节状态以及 `robot_state_publisher` 最终发布的 TF。

### 15：Navigation 传感器接口——LaserScan、Range 与传感器 TF

本章只保留 Navigation 直接相关的二维传感器接口：

```text
sensor_msgs/LaserScan
sensor_msgs/Range
header.stamp
header.frame_id
sensor frame -> base_link
```

重点回答“Topic 明明有数据，为什么 costmap / SLAM 仍然不能消费”。相机、`Image`、`CameraInfo`、`PointCloud2` 不在这里展开，统一留到阶段 D。

### 16：robot_localization——Odometry + IMU 的状态估计接口

理解 EKF/UKF 的输入输出契约、`map_frame` / `odom_frame` / `base_link_frame` / `world_frame`、时间、covariance 和二维模式；不要求先深入滤波器数学证明。

重点是把第 12 章已经发布的 `/odom`、`/imu/data_raw` 接入状态估计，并判断 frame、符号、单位、时间和 covariance 是否满足融合器要求。

### 17：SLAM 与定位——地图、AMCL 与 `map -> odom`

把“建图”和“已有地图后的定位”放在同一条坐标链里理解：

```text
建图：
/scan + odom + TF
       -> SLAM
       -> /map + map -> odom

已有地图运行：
/map + /scan + odom + TF
            -> AMCL
            -> map -> odom
```

重点不是算法推导，而是谁消费哪些数据、谁负责 `map -> odom`、为什么 `odom -> base_link` 与 `map -> odom` 不能由同一类误差模型替代。

### 18：Navigation / move_base

理解：

```text
localization
 -> costmap
 -> global planner
 -> local planner
 -> cmd_vel
```

重点是 global/local costmap、planner、机器人位姿、传感器障碍物和 `/cmd_vel` 之间的数据依赖，以及上游 TF / odom / sensor 错误如何传播到导航行为。

### 19：AGV 跨层故障定位

建立典型问题矩阵：

- 有传感器数据但 costmap 无障碍物；
- odom 连续但定位漂移；
- TF extrapolation；
- `cmd_vel` 正常但底盘行为错误；
- IMU 方向 / ENU-NED 错；
- 左右轮符号、单位、gear ratio 错；
- timestamp 延迟导致融合异常。

验收：从 Driver 的 Topic 和 frame 输出开始，能够沿 `Topic -> TF -> state estimation / localization -> costmap -> planner -> cmd_vel` 逐层缩小问题范围。
