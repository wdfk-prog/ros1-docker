## 阶段 C：AGV 数据链路与 Navigation（15～22）

目标不是转型成导航算法工程师，而是能够理解驱动数据怎样进入定位、建图、代价地图和规划。

### 15：TF / tf2 与坐标系

必须深入理解：

```text
map
 -> odom
 -> base_link
 -> sensor frames
```

重点：frame_id、静态/动态 TF、时间查询、TF extrapolation。

### 16：URDF / robot_state_publisher / joint_state

理解整机几何关系和关节状态如何建立 TF tree。

### 17：Odometry、Encoder、IMU 与运动数据

重点：轮速、里程计、IMU、协方差、坐标系约定、符号和单位。

### 18：LiDAR、超声波、相机等传感器接口

重点关注驱动输出消息格式和上层消费者要求。

### 19：robot_localization 与传感器融合接口

理解 EKF/UKF 的输入输出契约、frame 配置、时间和协方差；不要求先深入滤波器数学证明。

### 20：SLAM 基础与驱动接口

理解 SLAM 需要什么传感器、TF、odom 和时间关系；算法推导按需扩展。

### 21：Navigation / move_base

理解：

```text
localization
 -> costmap
 -> global planner
 -> local planner
 -> cmd_vel
```

重点是数据依赖和故障传播。

### 22：AGV 跨层故障定位

建立典型问题矩阵：

- 有传感器数据但 costmap 无障碍物；
- odom 连续但定位漂移；
- TF extrapolation；
- `cmd_vel` 正常但底盘行为错误；
- IMU 方向/ENU-NED 错；
- 左右轮符号、单位、gear ratio 错；
- timestamp 延迟导致融合异常。

验收：从驱动输出开始，能够沿 Topic/TF/Navigation 数据链逐层缩小问题范围。
